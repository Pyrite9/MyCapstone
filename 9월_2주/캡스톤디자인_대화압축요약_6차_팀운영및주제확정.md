# 캡스톤디자인 — 6차 압축요약 (팀 운영 + 주제 확정 세션)

## 1. 팀 운영 — 랜덤 배정 대응

- 조원 6명 랜덤 배정, 배경 사전 파악 불가 상태로 시작.
- 팀 내 외국인 조원 1명(중국인, 번역기 주로 사용) 확인됨. 실시간 음성/대면보다 텍스트 기반 소통이 유리하다는 판단 하에 운영 방식 전체를 텍스트 중심으로 설계함.
- 담임교수에게 해당 조원 소통 방법 조언을 요청하는 메일 발송 결정 (평가성 질문 배제, "어떻게 접근하면 좋을지" 프레임으로 접근).
- 카카오톡 단체방을 메인 채널로 확정, 공지문에 "짧고 완성된 문장", "이해 안 되면 다시 물어봐도 된다"는 문구 포함.
- 디스코드 서버 구성 완료: `#공지`, `#일반`, `#회의록`, `#아이디어`(텍스트) + `일반`(음성). 번역기 조원을 고려해 채널명 병기(예: `#아이디어-想法`) 권장.
- 조원 실기술 수준 확인: **전원 초보 단계**(오늘 첫 GitHub 커밋 수준). 두각을 드러내는 조원 없음 → 역할 배분 전 "실력 관찰 기간" 전략은 재검토 필요, 예시/설명 난이도를 전면 하향 조정함.

## 2. 기술 스택 확정

- **React(프론트) + Spring Boot(백엔드) 고정.** 커리큘럼 내 스택이며 팀 초보 수준을 고려한 선택.
- 이 결정으로 인해 5차까지 검토했던 후보 중 스택과 결이 안 맞는 것들(액터모델 게임서버, 오디오 신호처리, 금융데이터 분석, 네트워크 부하비교 등)은 전부 폐기함. Chzzk 연동 주제도 이번 세션에서 논외 처리(팀 소통 중심 세션으로 전환).

## 3. 아이디어 브레인스토밍 — 9개 신규 후보 및 필터링

조원 자유 제출로 9개 아이디어 수합 후 필터 적용:

| 아이디어 | 결과 | 사유 |
|---|---|---|
| 토막 (자습 요약) | 유지 | 필터 통과, 기존 후보 |
| 유가이력 (주유소 가격 추이) | 유지 (재검증됨) | 하단 4항 참고 |
| 잇썸 (식사약속 매칭) | 유지 (재설계됨) | 하단 5항 참고 |
| 책바퀴 (캠퍼스 중고서적) | 유지 (재검증됨) | 하단 4항 참고 |
| 캡처AI | 기각 | LLM 제거 시 서비스 자체가 안 남는 전형적 케이스, 유사 기능(빅스비 비전 등) 이미 존재 |
| 틈새 (빈 시간 미션) | 기각 | 범위 추상적, 유사 앱(뽀모도로류) 다수 |
| 한국어 도와줘 (외국인 유학생 AI 도우미) | 기각 | LLM 의존도 100%, 파파고·듀오링고 등으로 포화 |
| AI 메뉴 추천 | 기각 | 완전 레드오션, LLM 제거 시 무의미 |
| AI 발표 도우미 | 기각 | 감마·Tome 등 포화, LLM 래퍼 성격 강함 |

## 4. 필터 재검증 사례 (중요 — 검증 없이 탈락/통과 판단 금지 원칙 재확인)

### 4-1. 유가이력
- **1차 판단(오판)**: "오피넷이 이미 가격 예측+개인화 추천 기능을 제공한다"는 이유로 탈락 후보로 분류.
- **관리자 반박 및 재검증**: 오피넷은 지역/전국/정유사 단위 추이 그래프만 제공하며, **개별 주유소 하나의 일별 가격 히스토리 그래프는 제공하지 않음**(공식 사이트 직접 확인 완료). 아이디어 원안은 "주식 차트처럼 이동평균 대비 현재가 위치"를 보여주는 것으로, 오피넷과 층위가 다름.
- **결론**: 탈락 취소, 유력 후보로 복귀. **"이미 있다/없다"는 검색 한두 건이 아니라 공식 사이트 직접 확인까지 거쳐야 함**을 재확인한 사례.

### 4-2. 책바퀴
- 에브리타임 중고장터 + 기존 학술 선례(BookCue 등)로 시장 포화 확인됨. 다만 "학과-과목 매핑" 구조로 검색 방식 자체를 차별화하면 방어 가능하다고 판단, 유지.
- 양면시장 콜드스타트 문제는 인정하고, 초기 데이터는 조원 보유 교재로 시드하는 현실적 전략으로 대응.

### 4-3. 잇썸
- 원안(단순 밥친구 매칭 게시판)은 양면시장/실시간 콜드스타트 문제 그대로 존재.
- **재설계**: 게임 파티모집 UX 차용 — 참여 전엔 인원수만 공개, 참여해야 신원(이름/학과) 공개. 기존 밥약 앱들(프로필 우선 노출)과 반대 방향이라 차별화 포인트로 확인됨(웹검색으로 유사 사례 없음 확인).
- 안전장치로 재학생 인증 필수 적용, 인원 마감 시 자동 종료.

## 5. 조원 투표 결과

- 1차 투표(3개 추리기): 유가이력(4표) 1위, 토막·잇썸·책바퀴 3표 동률로 상위 4개.
- 유가이력 재검증(위 4-1) 이후 탈락 후보 없음 재확인.
- 콜드스타트 심각도 비교 결과 **잇썸을 드랍 권장했으나, 조원 재투표(잇썸 vs 토막)에서 잇썸이 과반 획득** → 관리자 판단: 이번 주는 잇썸으로 발표 준비, 반려 시 토막으로 대체 진행하는 전략 채택.
- 최종 발표 후보 3개: **유가이력, 책바퀴, 잇썸** (토막은 백업으로 대기, 명세 미작성 상태)

## 6. 오피넷 Open API 조사 결과 (유가이력 기술 검증)

- 일반 API 호출 한도: **300call/일** (공식 사이트 확인)
- 사용 API: `aroundAll.do` (반경 내 주유소 일괄 조회, 콜 1회로 다건 반환)
- 좌표계 주의: **KATEC 좌표** 사용 (WGS84 아님, 변환 필요)
- 유종 2종(휘발유 B027, 경유 D047) 모두 수집하기로 확정 — 콜 소모량 하루 2~6콜 수준으로 300call 한도 대비 매우 여유 있음
- 1차 데모 범위: 반경 1개 구역, 하루 1회 수집으로 시작, 구현 검증 후 확장 여부 판단

## 7. 책바퀴 ISBN 조회 API 검증

- 원래 검토했던 **알라딘 Open API는 서비스 종료됨** (확인 완료)
- 대체안: **네이버 책 검색 API**(메인, query에 ISBN 입력) + **국립중앙도서관 서지정보 API**(폴백, 2차 목표)
