COVER 업무 기능도·기술서 변경 사항
TITLE 업무 기능도 및 업무 기술서 변경 사항
SUB 대상 문서: 업무 기능도 및 업무 기술서 v1.2에서 v1.3으로 변경
BOX 변경 범위: 업무 기능도 그림, 단위 업무 정리, 기능 목록, 1단계 접근 범위, 동료평가 임시 저장
BOX 구    성: 단위 업무 35개에서 29개, 1단계 기능 8개 유지
BOX 함께 고칠 문서: 프로젝트 개요서의 인증 항목과 메일 발송 항목

S 변경 사항
H 업무 기능도 그림
O 위치: [그림 1] 업무 기능도
O 변경 전: 단위 업무를 하나씩 상자로 나누어 세로 방향 쪽에 왼쪽에서 오른쪽으로 펼쳐 그렸음
O 변경 이유: 지난 발표에서 단위 업무를 모두 상자로 나누지 말라는 의견을 받음
O 변경 후: 그림이 있는 쪽만 가로로 바꾸고 위에서 아래로 내려가는 구조로 다시 그렸으며, 단위 업무는 기능마다 아래에 상자 하나로 묶어 표시함
O 표시 방식: 업무 영역마다 색을 달리하고, 기능마다 기능 ID를 함께 표시함

H 단위 업무 정리
O 위치: [그림 1] 업무 기능도, [표 2] 회원 관리, [표 3] 과제 관리, [표 6] 동료평가, [표 7] 교수 열람
O 변경 전: 로그인과 로그아웃, 과제 등록, 제출 전 확인, 조 선택처럼 독립된 업무가 아닌 단계까지 단위 업무로 나누었음
O 변경 이유: 저장, 확인 창, 화면 이동, 같은 내용의 상세 보기까지 나누어 기능도가 필요 이상으로 세분되었음
O 변경 후: 단위 업무 13개를 6개로 합쳐 7개를 줄였으며, 임시 저장 1개를 더해 단위 업무는 35개에서 29개가 됨
D 합친 결과와 새 번호: 회원 등록(M-1-1), 로그인·로그아웃(M-2-1), 과제 정보 입력(A-1-1), 근거 기록 조회(E-1-1), 평가 제출(E-2-3), 시간순 기록 조회(V-1-1)
D 합친 단계의 처리 내용은 해당 기능의 업무 규칙으로 옮김
D 초대 링크 발급과 링크로 합류는 사용자와 업무 규칙이 달라 그대로 둠

H 기능 목록 정리
O 위치: 요약 상자, [그림 1] 업무 기능도, [표 1] ~ [표 7], 업무 규칙의 ID 표시
O 변경 전: 기능 ID에 영역별 영문 코드 3자에서 4자와 두 자리 번호를 썼고(REC-01, REC-01-1), [표 1]에 개요서 번호 열과 구현 단계 열이 있었음
O 변경 후: 기능 ID를 영문 한 글자와 번호(R-1)로, 단위 업무는 그 뒤에 번호를 하나 더 붙여(R-1-1) 줄였고, [표 1]은 기능 ID, 기능, 사용자만 남김
D 영역 글자는 회원 관리 M, 과제 관리 A, 조 운영 T, 과정 기록 R, 동료평가 E, 교수 열람 V이며, 영역 안의 순서와 번호는 바꾸지 않았음
D 그림 1에도 구현 단계를 표시하지 않음

H 1단계 접근 범위
O 위치: 업무 기술서 공통 업무 규칙의 주석
O 변경 전: 1단계의 권한 확인을 로그인 여부, 회원 유형, 조장 여부로 한정하고, 다른 조 기록 차단은 2단계에 구현한다고 적었음
O 변경 이유: 같은 1단계 기능인 산출물 업로드와 동료평가 입력은 모두 조 소속을 확인해야 처리할 수 있어, 주석과 본문 규칙이 맞지 않았음
O 변경 후: 접근 범위를 1단계부터 적용하고 과제 단계 구분만 2단계에 구현하며, 화면과 데이터는 늘지 않음

H 동료평가 임시 저장
O 위치: 요약 상자, [그림 1] 업무 기능도, [표 1] 주석, [표 6] 동료평가 단위 업무, 동료평가 입력 규칙
O 변경 전: 동료평가는 대상 조원 전원의 점수를 입력하고 제출해야만 저장되었음
O 변경 이유: 조원이 5명이면 점수 24개와 의견을 한 번에 입력하는데, 제출 전에 화면을 닫거나 접속이 끊기면 모두 사라짐
O 변경 후: 동료평가 입력에 임시 저장(E-2-2)을 추가하고 2단계에 구현함
D 점수를 일부만 입력해도 저장할 수 있고 다시 열면 이어서 입력하며, 교수에게는 보이지 않고 제출 현황에 미제출로 표시됨
D E-2-2는 제출 전 확인에서 임시 저장으로 바뀌었고, 평가 제출은 E-2-3을 그대로 씀

H 함께 고칠 문서
O 프로젝트 개요서의 인증 항목은 학교 이메일 인증으로 남아 있어 학교 구글 계정 로그인으로 고칠 예정임
O 프로젝트 개요서의 초대·알림 메일 발송 항목은 초대 링크 방식에 맞추어 고칠 예정임
