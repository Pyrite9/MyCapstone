# 캡스톤디자인 — 프레젠테이션·문서 디자인 명세 v3
 
> 대상: 캡스톤디자인 팀이 만드는 모든 발표 자료(HTML 덱, 목업, 다이어그램, 대본 docx). 어떤 주제든 동일 적용.
> 원칙: 팔레트·타이포·모티프·금지 규칙은 **모든 주제 섹션에 동일 적용**. 주제마다 바뀌는 건 텍스트·아이콘·데이터뿐 — 그래야 여러 주제를 한 덱에서 다뤄도 "한 팀이 만든 발표"로 읽힘.
> v2(2026.09.08)에 §13 문서형 명세서(PDF) 규칙을 추가한 것(2026.09.14). §0~§12 덱 규칙은 v2와 동일. 구 파일은 폐기.
 
---
 
## 0. 컨텍스트
 
- 발표 주체: 공학계열 개발자 팀(React/Spring Boot 스택).
- 청중: 담당 교수 + 동급생. 기술 심사보다 서비스 타당성·완성도 심사에 가까움.
- 톤: 신뢰감 + 실용성. "번지르르한 피치"가 아니라 "이 팀이 실제로 구현할 수 있다"는 인상이 우선.
- LLM을 쓰는 주제라도 데이터·로직·UX가 주인공으로 보이게 구성. LLM은 도구로 표현.
## 0-1. 테마 고정
 
- **라이트 테마 고정** (`color-scheme: light only`). 다크모드 대응 금지.
- 강의실 스크린·프로젝터에서 다크 배경은 가독성·밝기 대비 예측 불가.
## 0-2. 발표 환경 (확정)
 
- 강의실 PC는 **항상 온라인** → Noto Sans KR은 Google Fonts 웹폰트 로드로 충분. 임베드 불필요. fallback 스택(`'Noto Sans KR', 'Malgun Gothic', sans-serif`)만 선언해 둠.
- 스크린 비율 **16:9 확정**. 레터박스 처리 불필요, §3의 1920×1080 scale 방식 그대로.
- 발표 시간 제한 없음. 자체 상한은 §12 대본 분량으로 관리.
- 인쇄·PDF 제출본: 덱과 별개의 **문서형** 규칙으로 §13에 정의. 덱의 scale 방식은 print 미지원 전제 그대로.
- **애니메이션·전환 허용.** 단 규칙: 슬라이드 진입 시 1회 재생, 300ms 이내, 자동 반복·자동 재생 없음, 발표자 키 입력 없이 콘텐츠가 바뀌지 않음. 장식이 아니라 순서·관계를 보여주는 용도(단계 순차 등장, 구조도 화살표 순차 표시)로만.

## 1. 팔레트
 
특정 주제의 은유에 종속시키지 않음. 팀 정체성(정확하고 절제된 엔지니어링 태도) 기준의 무채색 우위 팔레트.
 
| 역할 | 색 | 비중 |
|---|---|---|
| 베이스 | `#EDE9E3` 웜 그레이 | 배경 전체 |
| 주 색상 | `#332C4A` 딥 플럼 | 60–70%, 제목·주요 도형 |
| 보조 | `#9C8B72` 타우프 | 20%, 서브텍스트·보조 도형 |
| 강조 | `#B8863B` 머스타드 골드 | 5% 이하, 진짜 강조할 지표·CTA만 |
| 텍스트 | `#211D2B` (플럼 톤 섞은 블랙) | 본문 |
| 구분선·그리드 | `#D9D3C9` | 표 행 구분, 차트 그리드, 목업 테두리 |
 
- 주제별로 색을 바꾸지 않음. 바꾸는 순간 짜깁기로 읽힘.
- 강조색은 "이 발표에서 제일 중요한 숫자 1개" 수준으로만. 버튼마다 칠하면 의미 없어짐. 골드가 들어간 슬라이드에서는 다른 곳에 골드를 쓰지 않음.
### 1-1. 반전 슬라이드(딥플럼 배경) 전용
 
| 역할 | 색 |
|---|---|
| 히어로·본문 | `#EDE9E3` |
| 서브텍스트·캡션 | `#C9BFB0` (반전 전용 보조색, 대비 6.4:1) |
 
- 반전 슬라이드에 타우프 `#9C8B72` 직접 사용 금지(대비 2.7:1). 골드도 사용 안 함.
### 1-2. 목업 전용 시맨틱 2색
 
| 역할 | 색 | 용도 |
|---|---|---|
| 경고 | `#9E4A3A` 벽돌 레드 | 미이행·기한 경과·노쇼 등 위험 상태 |
| 정상 | `#5F7A4E` 올리브 그린 | 정상·완료 상태 |
 
- **목업 화면 내부에서만** 허용. 슬라이드 본문·표·구조도·KPI 카드에는 쓰지 않음.
- 상태 배지 배정: 기본/진행 = 딥플럼 채움, 주의/임박 = 골드 채움, 위험 = 경고, 정상 = 정상. 글자는 배경 위 흰색 또는 베이스색. 비활성/완료 텍스트는 타우프.

## 2. 타이포그래피
 
- 단일 패밀리 **Noto Sans KR**. 두 번째 서체 없음. 목업 내부도 동일.
- 위계는 weight + 크기 + 자간으로만:
  - 타이틀: Black(900), 자간 살짝 좁게
  - 본문: Regular(400) / Medium(500)
  - 라벨·캡션: Medium(500), 작게 — **all-caps 금지**
- 한 슬라이드에 굵기 3단계 이하.
## 2-1. 크기 (1920×1080 기준, 노안 교수·프로젝터 뒷자리 기준)
 
| 역할 | 크기(px) | weight |
|---|---|---|
| 히어로(한 줄 문구) | 117 (섹션 디바이더 142) | 900 |
| 섹션 제목 | 67 | 900 |
| 소제목(단계·항목명) | 48 | 700 |
| 본문 | **43** | 400/500 |
| 표 본문·헤더 | 43 (본문과 동일) | 400 / 700 |
| 캡션·메타 | 27 | 500 |
| 차트 축 라벨·범례 | 27 | 500 |
| 구조도 박스 텍스트 | 약 40 | 500 |
| 목업 본문 | 22 × 프레임 축소 배율 (시각 참고용, §8) | — |
 
- 본문이 43px에 안 들어갈 만큼 텍스트가 많으면 **크기를 줄이지 말고 문장을 줄이거나 슬라이드를 나눔**. 표도 동일 — 안 들어가면 행을 줄이거나 장 분할.
- 자동 축소(autofit)는 안전장치로만 두고 하한 0.6. 하한에 걸리면 콘텐츠 문제로 보고 분할.
- 캡션 등급은 "안 읽혀도 발표에 지장 없는 정보"에만.
- 위 표보다 작은 기준으로 만들어진 구 덱은 재편집 시 이 표로 맞춤.
## 2-2. 줄바꿈
 
1. 전역 `word-break: keep-all;` (한글 글자 단위 끊김 방지). `overflow-wrap: break-word;`는 긴 영단어·URL 방어용으로만.
2. role별 컨테이너 max-width 고정(§3 수치).
3. 확정 텍스트는 줄바꿈 위치를 `<br>`로 명시. 텍스트 수정 시 `<br>` 위치 재확인.
## 2-3. 본문 인라인 강조
 
- **weight 700만.** 색 변화·배경 마커·밑줄 없음.
- 한 슬라이드에 강조 2곳 이하.
## 2-4. 숫자·단위·날짜 표기
 
| 항목 | 규칙 | 예 |
|---|---|---|
| 천단위 | 콤마 | `1,650원` |
| 단위 | 붙여씀 | `12km` `83.9%` `300콜` |
| 날짜 | `YYYY.MM.DD` | `2026.09.10` |
| 기간 | `N일` | `7일 / 30일` |
| 예시 수치 | 슬라이드 하단 캡션 "수치는 예시" 1회 | 숫자 옆 `*` 사용 안 함 |

## 3. 레이아웃·스테이지
 
- **1920×1080 고정 스테이지를 뷰포트에 scale**하는 방식. px 크기 절대 보장, 뷰포트마다 재배치 안 함.
- 16:9 고정 비율, 세로 전환.
- **안전 마진 120px** (상하좌우). 본문 컨테이너 **max-width 1400px**. 2단 배치(목업+본문 등) 좌우 간격 80px. 단락 간격 32px, 제목–본문 간격 48px.
- **하단 구석**: 좌하단 = 섹션 컨텍스트(27px, 타우프, 낮은 대비). 우하단 = 페이지 인디케이터. 표지에는 둘 다 없음.
- 페이지 인디케이터: 원형 점 대신 **가로 pill 바**. 비활성은 짧고 낮은 투명도, 활성은 넓어지며 주 색상으로 채움.
- 섹션 디바이더에는 "주제 01/02" 같은 번호 대신 **도메인 라벨**(고객군 또는 업종, 2~4어절).
## 3-1. 슬라이드 종류와 구성
 
- **표지**: 라이트 배경(반전 아님). 좌상단 27px 컨텍스트("캡스톤디자인 · 주제 심의" 등), 좌하단 제목(67px 900) + 부제(43px 타우프). 우하단 메타 없음. 조 번호·발표자는 표지에 올리지 않음(대본 표지에만).
- **히어로+디테일 2장 세트**: 문제 제기·차별점 같은 **주장 장에만** 적용. 히어로는 반전 배경 한 줄, 디테일은 라이트 배경 본문.
- **자료 장**(목업·표·구조도·근거·예상 질문)은 히어로 없이 단독. 섹션 제목(67px) + 내용.
- **예상 질문 장**: 질문(48px 700, 골드 tick) + 답변(43px) 병기. 한 장에 2개 이하. **주제별로 그 주제 바로 뒤에 배치**, 덱 끝에 몰지 않음.
- **엔딩 슬라이드 없음.** 덱 마지막 장 = 마지막 주제의 예상 질문. 발표 종료는 발표자가 구두로("이상입니다. 질문 받겠습니다") — 대본 마지막 줄 고정.
- 섹션 컨텍스트 표기가 필요하면 라벨화하지 말고 하단 좌측 소형 텍스트로만.

## 4. 위계 표현 (밑줄·컬러바 금지 대안)
 
- 제목 강조: 베이스와 다른 톤의 **배경 블록**으로 타이틀 영역 구분.
- 섹션 전환: **여백 확대 + 배경색 베이스↔딥플럼 반전**.
- 카드·박스: **각진 사각형(radius 0~4) 하나로 고정**. 그림자 없음. "카드 킷" 느낌 배제.
- **항목 나열 — 구조에 따라 택일, 한 슬라이드에 한 종류만**:
  - 순차 구조: **숫자 + 작은 골드 tick**. 감싸는 배경·테두리 없음. 강조 단계는 tick 두께나 숫자 색만 변경.
  - 병렬 나열: **Tabler outline 라인 아이콘 단색(딥플럼), 배경·배지 없음**, 1920 기준 64px. 의미가 맞는 아이콘이 없으면 생략(억지로 넣지 않음).
- 타임라인: 마일스톤에 **골드 점만**.

## 5. 표
 
- 텍스트 43px(본문과 동일). 헤더 700, 본문 400, 숫자 열 500. **골드 사용 안 함.**
- 헤더 배경 없음. 헤더 위·표 아래 **딥플럼 3px 선**, 행 사이 `#D9D3C9` 1px 선. 세로선 없음. 줄무늬 없음.
- 셀 패딩 1920 기준 상하 20 / 좌우 28. 좌측 정렬, 숫자 열은 우측 정렬.
- 안 들어가면 행 축소 또는 장 분할. 열 4개 이하 권장.

## 6. 다이어그램·구조도 (SVG 인라인)
 
- 박스는 각진 사각형, 연결선은 직선 + 직각 코너. 곡선·점선 금지(차트 평균선은 §7 예외).
- **연결선 모티프는 다이어그램 내부에서만 허용.** 장식으로 확장하지 않음(§10 참조).
- 배치 기본형: 왼쪽 화면군 / 가운데 도메인 + 하단 DB / 오른쪽 외부 의존. 가로 화살표는 주된 호출 관계 1개씩만.
- **박스 색 규칙**:
  - 도메인·DB(팀이 구현하는 서버 측): **딥플럼 채움**, 글자 베이스색.
  - 화면군(팀이 구현하는 클라이언트): 흰 채움 + **딥플럼 4px 굵은 테두리**, 글자 텍스트색.
  - 외부 의존(API·지도 등): 흰 채움 + 딥플럼 2px 기본 테두리, 글자 텍스트색.
  - 연결선·화살표 머리: 딥플럼 3px, 삼각 머리.
- 캔버스 1300 기준, 글자폭 추정 기반 자동 축소 `fit()` 적용. 넘침 0 확인 후 확정.
- 인원수·담당자 표기는 역할 배정 확정 전엔 넣지 않음.

## 7. 차트
 
- 주 시리즈: **딥플럼 실선** 5px. 평균·보조선: **타우프 점선** 4px, 대시 18 / 간격 14 이상(축소 후에도 점선으로 읽히게). 이 점선은 §6 점선 금지의 유일한 예외.
- 가로 그리드 `#D9D3C9` 1px. 세로 그리드 없음. 축선은 그리드로 대체.
- **오늘 값(현재 값)만 골드 점(반지름 10) + 골드 라벨 700.** 그 슬라이드의 골드는 이것 하나.
- 시리즈 최대 2 + 평균선 1. 범례는 차트 아래 가로, 27px.
- 축 라벨 27px 타우프. 숫자 표기는 §2-4.

## 8. 목업(프로토타입 화면)
 
- HTML iframe 인라인. 이미지 파일 의존 없음.
- **목업은 시각 참고용.** 슬라이드는 좌 목업 / 우 본문 43px로 핵심 항목 텍스트 병기(2단, 간격 80). 목업 안 글자가 읽히는지에 발표를 의존하지 않음.
- 흰 바탕, 텍스트 `#211D2B`, Noto Sans KR, 위계는 제목 700 / 본문 400 / 메타 타우프.
- 강조 골드 1색 + 상태 배지에 한해 §1-2 시맨틱 2색. radius ≤4, 그림자 없음.
- 아이콘: Tabler outline 단색 딥플럼. 활성 탭만 골드 허용.
- 프레임: 390×844, **1px 타우프 테두리 + radius 4**, 베젤·노치·상태바 없음. 슬라이드 높이에 맞춰 자동 축소.
- **지도 영역**: 팔레트 도식(인라인 SVG — 도로 `#D9D3C9`, 배경 `#F4F1EC`, 핀 골드 1개, 장소명 흰 라벨). 실제 지형 아님. 목업 하단 캡션 **"지도는 도식"** 필수.
- 데이터는 실제 지명·실제 항목명 사용, 수치는 예시임을 슬라이드에 명시(§2-4).
- 이미지 클릭 시 확대.

## 9. 외부 서비스 화면 인용
 
- 원본 캡처 그대로 사용(색 보정·흑백 처리·마스킹 없음). 골드 표시 등 오버레이 금지.
- **1px 타우프 테두리** + 하단 캡션 **"출처: 도메인, YYYY.MM.DD 캡처"** 필수(27px 타우프).
- 좌 캡처 / 우 본문 2단 또는 단독. 캡처는 슬라이드 폭의 절반 이하.
- **발표 직전 재캡처** — 상대 서비스가 기능을 추가하면 슬라이드 주장이 거짓이 됨. 캡처일이 발표일과 2일 이상 차이 나면 재확인.

## 10. 절대 금지 (매 슬라이드 재확인)
 
- 제목 밑줄, 엣지 컬러 바·스트라이프, 카드 한쪽 면 보더
- 모든 카드 동일 radius + 동일 회색 그림자
- **원형 숫자·아이콘 배지** — "컬러 원 안에 숫자/아이콘" 조합 전면 배제. 사각 배경 위 아이콘도 동일하게 금지
- **eyebrow 라벨** — 불릿 점 + 자간 넓힌 ALL-CAPS + 미들닷(·). 개별 요소도 재사용 금지
- **회로 트레이스 장식** — 세로 레일·직각 꺾임·stub를 히어로·표지·디바이더·번호 리스트·타임라인 어디에도 쓰지 않음. 예외: 다이어그램 SVG 내부 연결선, 표 구분선
- 개발자 클리셰 장식 — 모노스페이스 라벨, 터미널 `$`, `</>` 아이콘, git diff +/- 배지
- 근거 없는 블루/그레이 디폴트 팔레트
- 버튼·링크 텍스트에 습관적 "→"
- 주제 섹션마다 팔레트·모티프 다르게 적용
- 다크모드 대응
- 반전 슬라이드에 타우프·골드 텍스트
- 시맨틱 색(§1-2)을 목업 밖에서 사용
- 한 슬라이드에 번호 리스트와 아이콘 나열 혼용

## 12. 발표 대본 (docx) 형식
 
### 구조
- 표지: 제목(26pt 플럼) / 부제(15pt 타우프) / 조 번호 · 발표자 · 발표 일자 · 대응 슬라이드 · 작성일 → 페이지 나눔
- 본문: `N. 주제 (슬라이드 a–b)` 섹션 → `NN–NN 섹션 — 히어로 문구 / 디테일 제목` 소제목(골드 번호 + 하단 괘선) → 본문 11pt Malgun Gothic. 히어로+디테일 2장은 소제목 하나로 묶음.
- **슬라이드 넘김 표기**: 슬라이드 경계마다 가로 괘선 + `페이지 넘김 → N`(N = 다음 슬라이드 번호). 세트 안에서도 표기함.
- 마지막 `예상 질문과 답변`: `Q.` 굵게 + 답변 들여쓰기(슬라이드에 올린 답의 전문).
- 마지막 줄 고정: "이상입니다. 질문 받겠습니다."
### 분량
- 히어로 장 1~2문장 / 디테일 장 3~5문장(40~60초) / 목업 장은 화면 요소 순서대로 3문장 내외 / 예상 질문 장은 답변 전문.
- 자체 상한: 주제당 5분 내외, 발표 전체 30분 이내. 제한이 없어도 교수 집중력이 기준.
### 읽기 표기
- 힘줘 읽을 구간만 **굵게(700)**, 슬라이드당 2곳 이하.
- 문단 사이 빈 줄 = 한 박자 쉼. `[클릭]` 같은 기호는 쓰지 않음(넘김은 위 괘선 표기로만).
- 숫자는 한글로 풀어 씀("천육백오십 원").
### 문체
- **사람이 그대로 읽는 문서** — "읽는 법"·작성 규칙 같은 메타 문단 금지.
- 화자는 팀 시점 "저희". 개인 경험 대목만 "제가/저". 도입에서 스택 언급 안 함(공통 기술 기반 장에서 처음).
- 발표자명·조 번호는 확정 전 `○○○` 빈칸.

## 13. 문서형 명세서 (PDF) — 2026.09.14 확정
 
> 담임교수 컨펌용 `캡스톤_주제명세.pdf`에 적용한 규칙. 발표 덱(§1~§12)과는 목적이 달라 위계·색·밀도가 다르다. 팔레트·서체·금지 규칙(§10)은 공유.
 
### 13-1. 성격
- **설계 문서**. 참조용이지 설득용이 아님. 히어로 문구·한 줄 슬로건·여백 큰 페이지 없음.
- 문서에 쓴 건 전부 질문 대상 — 조원 누구든 답할 수 있는 내용만. 팀 내부 용어(시드, 2차 범위, 공통 절) 금지.
### 13-2. 판형·서체
- A4 세로, 여백 20mm 균일. 머리글 좌 "캡스톤디자인 주제 명세", 바닥글 중앙 `N / 총`.
- Noto Sans CJK KR 임베드(웹폰트 아님). 본문 10pt, 행간 1.55, `word-break: keep-all`. 표 9pt. 캡션 8.5pt.
- 위계: 장 14pt Bold + 하단 딥플럼 2px 선 / 절 11pt Bold / 항 10pt Bold. 크기 차이 최소, 번호로 위계 표시.
- **흑백 기조.** 텍스트 `#211D2B`, 선 `#D9D3C9`, 제목만 딥플럼 `#332C4A`. 골드·시맨틱 색 사용 안 함.
### 13-3. 표
- 헤더 배경 `#EDE9E3`, 헤더 상단 딥플럼 1.5px, 행 사이 `#D9D3C9` 1px, 마지막 행 아래 딥플럼 1.5px. 세로선 없음. 외곽선 없음.
- 셀 패딩 상하 1.8mm / 좌우 2.5mm. 좌측 정렬. 열 5개까지.
- 첫 열(구분·번호·항목)은 줄바꿈 금지.
- 표가 페이지에 걸쳐 끊기는 것을 피함 — 걸리는 절은 새 페이지에서 시작(`page-break-before`). 현재 목록: 1.9, 2.4, 2.5, 2.6, 2.9, 3.6 엔티티, 3.7, 3.9. 표 헤더는 페이지마다 반복.
### 13-4. 문체
- 표 안 개조식("~함 / ~없음"). 표 밖 한 줄(원칙·접근·차별점)은 서술체("~한다"). 예상 질문 답변은 존댓말(구두 답변 원문, 3문장 이내).
- 구어체·기호를 글 대신 쓰기(=, +, →)·외래어(폴백) 지양. 괄호 앞 띄어쓰기 없음. 강조는 Bold만.
- 용어는 모으지 않고 처음 나오는 절 아래 "※ 용어 — A: 뜻 · B: 뜻" 한 줄.
### 13-5. 그림
- 주제당 같은 자리에 같은 종류: x.2 비교(현행 vs 제안) / x.4 흐름(세로 스윔레인, 박스에 화면 번호) / x.4 상태 전이 / x.5 목업 / x.6 구조 / x.8 기술 과제 개념도. 주제별 개수가 어긋나지 않게.
- 전부 인라인 SVG, 캔버스 1300 기준, 1px `#D9D3C9` 테두리 박스 안에 배치. 박스 규칙은 §6 동일(도메인·DB 딥플럼 채움 / 화면군 4px 테두리 / 외부 2px 테두리). 현행 측 박스는 타우프 테두리·타우프 글자.
- SVG 안 서체는 `'Noto Sans CJK KR'`을 첫 순위로 — 미지정 시 폴백 폰트가 임베드됨.
- 캡션 "그림 N-k. 제목". 예시 수치가 들어간 그림은 캡션에 "수치는 예시".
- 넣지 않는 것: 엔티티 관계도(ERD 미작성 결정과 충돌), 시연 순서도, 리스크 절 그림.
### 13-6. 목업
- 기존 덱 목업을 재사용. 모바일 3장은 가로 나열(1px 타우프 테두리), PC 화면은 장당 별도 그림(최대 높이 108mm)·번호에 a/b/c/d.
- 구 팔레트(네이비·블루) 목업은 문서 팔레트로 색 치환해서 사용. 명세와 어긋나는 UI 요소(삭제된 기능·문구)는 HTML에서 제거 후 캡처.
- 캡션 "주요 화면 — 시각 참고용, 화면 내 수치는 예시 — 화면명 (x.5.n)".
### 13-7. 툴체인
- md(주제별 1개 + 부록) → `build_spec.py`(markdown → HTML, 그림·목업 인라인, 목업 열 제거, Q&A 문단 분리, BREAKS) → `topdf.py`(Playwright Chromium `page.pdf`, 머리글·쪽번호). wkhtmltopdf는 unpatched qt라 머리글·쪽번호 불가 → 사용 안 함.
- 그림은 `gen.py` + `svglib.py`로 생성. 문구 수정은 md, 그림 수정은 gen.py, 형식 수정은 build_spec.py의 CSS.
