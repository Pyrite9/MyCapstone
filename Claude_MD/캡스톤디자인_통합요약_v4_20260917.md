## 2. 확정 주제 — 발자국 (조별과제 과정기록 & 평가지원 서비스)

상세는 `캡스톤_주제명세_v1.2.pdf` 1장(3~11쪽)이 기준. 여기엔 결정 사항만.

### 2-1. 정의
- 조별과제의 산출물과 완료확인을 과정 기록으로 남기고, 그 근거를 보면서 사람이 동료평가를 입력하는 **PC 웹** 서비스.
- 원칙: **판단은 사람, 시스템은 근거만.** 점수 자동 계산·순위·가중치 없음. 고정 문구 "업로드 횟수는 기여도가 아닙니다 · 점수는 시스템이 계산하지 않습니다".
- 사용자 관점(팀 정의, 2026.09.16): **교수** = 동료평가 작업 지원 + 과정 확인 / **학생** = 조별과제 진행 도우미 + 조원 이탈 대비 과정 기록. 대본에 반영됨, 명세 1.1 사용자 행은 미반영 → v1.3에서 반영 예정.
- 성격: 학교 공식 시스템(LMS) 아님. 범위 밖: LMS 연동, 성적 산출.

### 2-2. 구조 결정
- **과제 하나에 조 여러 개.** 교수가 과제 생성·조마다 조장 지정 → 조장이 초대 링크로 역할 배정 → 조원이 기록. 권한 모델은 **조 단위** `[확정]`.
- **파일 본문 저장** `[확정]`. 오브젝트 스토리지, 버전 순, 최신 상단, 조원·교수 열람·다운로드, 조회·다운로드 집계 안 함.
- 완료확인: 산출물 + 파일 없는 **기여 항목**(회의 진행·자료 취합·일정 조율) 모두 대상. 담당자 보고 → 다른 조원 확인(여러 명 가능). 혼자 소급 입력 불가. 시각은 서버 기록.
- 동료평가: 2항목(역할 수행 / 팀 소통) 각 5점, 개별 입력, 조원 간 비공개, 결과는 교수만. 근거 패널(산출물·완료확인 종류별 분리)은 조원·교수.
- 기능 9개(1.4.1~1.4.9), 화면 9개(1.5.1~1.5.9), 엔티티 8개(회원·과제·조·조 참여·기여 항목·산출물·완료확인·평가).
- 외부 의존: 오브젝트 스토리지, SMTP만.

### 2-3. 범위
- 1차 핵심 7: 과제 생성·역할 배정·산출물·완료확인·근거 패널·동료평가·교수 열람.
- 1차 부가 2: 기여 항목·진척 시각화.
- 구현 순서: ① 인증·과제·역할 → ② 산출물 업로드·열람 → ③ 완료확인·기여 항목 → ④ 근거 패널·동료평가·교수 열람 → ⑤ 진척 시각화.
- **12.11까지 목표 흐름: 과제 생성 → 역할 배정 → 산출물 업로드 → 동료평가 입력** `[확정]`. 완료확인·기여 항목·진척 보드·조 단위 권한 과제는 12.12~2027.03.

### 2-4. 기술 과제
- 핵심: **조 단위 권한** — Spring Security 메서드 인가(`@PreAuthorize`), 조-사용자 소속 검사. URL 단위 권한으로는 "다른 조의 조원"을 못 막음.
- 그 외: 파일 업로드·오브젝트 스토리지 연동·버전 관리.

### 2-5. 리스크
1. 사후 일괄 입력 → 서버 시각·타인 확인으로 방어.
2. 보이는 기여 편향 → 평가 항목 분리·고정 문구.

### 2-6. 열린 항목
- `[구현 단계]` 교수 계정 생성 방식(1차는 시연용 계정 직접 생성), 데이터 보관 기간(교수와 협의), 파일 용량·형식 제한.
- `[열림]` 조원 역할 배정(5.1의 2명/2명/1명), ERD, API 명세, 화면 설계.
- LLM: 핵심엔 안 씀. 부가 후보 = 완료 보고 메모·파일 이력 요약을 근거 패널에 표시. 응답 없으면 빈 칸(의존 아님). 평가 초안 생성은 원칙 위반이라 금지.
